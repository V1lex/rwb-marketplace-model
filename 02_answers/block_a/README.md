# Блок А: ответы

Каждый вопрос — отдельный файл с запросом и комментарием о принятых решениях.
Все запросы обращаются только к `core`. Результаты выгружаются в [`results/`](results/),
контрольные цифры из задания сверяются автоматически ([`checks.sql`](checks.sql)):

```bash
make answers
```

Общие определения (одинаковы для всех вопросов, заданы в модели, а не в запросах):

* **Выручка** — сумма цен товаров без доставки по выкупленным заказам.
  «Выкуплен» = статус с `dim_order_status.is_revenue`, сейчас это только `delivered`.
* **Период** — по дате оформления заказа.
* **Покупатель** — человек (`customer_unique_id`), а не `customer_id` источника.

## 3. Средний чек заказа

| Средний чек | Строк в заказе | Единиц в заказе | Заказов |
|---:|---:|---:|---:|
| **159.88** | 1.039 | 1.142 | 96 478 |

Чек — свойство заказа: товары + доставка, одна строка `fact_order` = один заказ.
«Строка» — разная пара (товар, продавец), «единица» — штука товара. Единиц больше
строк, потому что в источнике каждая штука — отдельная строка `order_item_id`.
Если бы мы считали по позициям, получили бы 123.75 (средняя цена товара) или
139.97 (средняя позиция с доставкой).

## 4. Покупатели и повторные покупки

| Покупателей | Вернулись | Доля |
|---:|---:|---:|
| **96 096** | 2 997 | **3.12%** |

Ключ — `customer_unique_id`. `customer_id` в источнике выдаётся на каждый заказ
заново: с ним вышло бы 99 441 «покупатель» и ни одного повторного. Учитываются все
оформленные заказы: вопрос о том, вернулся ли человек за покупкой, а не о том,
доставили ли её. Если считать только выкупленные, получится 93 358 и 3.00%,
поэтому фильтр статусов здесь — осознанное решение.
